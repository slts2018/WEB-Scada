# 历史趋势（trendHistory）改造方案

> 目标：把历史趋势做成「能查、能看、能读数」的分析控件。
> 原则：只新增、不破坏现有契约（工程 JSON / REST / WS / Publish）；不引入新依赖；实时趋势（`trend`）语义不动。

---

## 1. 范围

### 本期要做

| # | 能力 | 说明 |
|---|------|------|
| 1 | 变量选择 | 设计端多选变量（带搜索/分组）；运行端图例点选显隐，可选允许增删 |
| 2 | 时间区间 | 预设（15m/1h/8h/24h/今天/昨天）+ 自定义起止（秒精度）+ 前/后平移 + 自动跟随/暂停 |
| 3 | 游标 | 单击落游标、可拖动、键盘微调、吸附最近采样点、读数面板；可选双游标 A/B 与差值 |
| 4 | 缩放 | 滚轮缩放（已有）、框选放大（新）、底部滑块（新）、双击还原（已有） |
| 5 | 数据 | 多变量一次查询、按跨度自动降采样/聚合、加载态/空态/错误态 |

### 本期不做

- 不改实时趋势 `trend` 的采样与打点语义（上一轮已单独改过）。
- 不改 `/api/ws/tags` 报文、Publish 包结构、变量元数据字段。
- 不改数据库表结构、不改历史写入的 measurement / 字段含义。
- 不引入新依赖（不装图表/时间/表格库），只用 ECharts + Element Plus 现有能力。
- 不做报表导出 PDF、不做报警联动分析。

## 2. 现状盘点（已有的不要再做）

| 能力 | 现状 | 位置 |
|------|------|------|
| 多曲线模型 | `props.curves`（≤ `TREND_MAX_CURVES` = 8 条，含颜色），设计端可增删 | `packages/core/src/factory/widget.ts`、`PropertyPanel.vue:516` |
| 历史查询 | 每条曲线各发一次 `GET /api/tags/{tagId}/history?start&stop&limit` | `TagController.history`、`InfluxHolder.queryHistory` |
| 前端缓存 | 按 `widgetId|tagId` 缓存 + 10s 轮询 + generation 作废 | `apps/web/src/shared/runtime/trendHistoryQuery.ts` |
| 时间范围 | 只有设计端预设 `props.range`（-15m/-1h/-8h/-24h/-7d） | `TREND_RANGES` |
| 运行端交互 | 原生 ECharts 叠层：滚轮缩放、拖拽平移、悬停读数、图例点选、导出图片 | `trendChartLive.ts`、`trendChart.ts`（`dataZoom inside`、`smooth`） |
| 位图回退路径 | 悬停读数、拖拽平移、双击还原 | `trendChartInteraction.ts` |
| 搜索条组件 | `TrendHistorySearchBar.vue` 已写好但**未接入**（死代码） | `components/runtime/` |
| 可复用的挂载方式 | 历史报警的「搜索条/分页条」按图元矩形定位挂到 HTML 层 | `alarmHistoryQuery.historySearchClientRect`、`Canvas2DRuntime.vue:500` |

### 缺口

1. 运行端不能选区间（只有设计端预设），没有前后平移、没有"自动跟随/暂停"。
2. 没有底部缩放滑块、没有框选缩放。
3. 游标只有"鼠标悬停 tooltip"，不能停留、不能拖动、没有差值读数。
4. 每条曲线单独发一次请求：8 条曲线 = 8 次 HTTP，且各曲线时间戳不对齐。
5. **`limit` 语义有坑**：Flux 是 `sort(asc) |> limit(n)`，取的是**区间内最早**的 N 个点。区间一长（24h × 1Hz = 86400 点，limit=240）就只拿到开头几分钟，看起来"右边没数据"。
6. 无加载态/空态；Influx 不可用时静默保留上一条曲线，用户不知道"是没数据还是没连上"。
7. 图例上的"当前值"取的是实时值，历史趋势里应该显示"游标处/最新历史点"的值。

### 3.4 游标读数

- 位置：图元右上角（或工具栏下一行的 HTML 面板，跟随图元定位）。
- 内容：游标时间（本地时区，秒精度）+ 每条曲线的值 + 质量色点（Good 绿 / Uncertain 黄 / Bad 红）。
- 取值语义：默认**吸附到最近采样点**（显示的就是真实点）；如需插值，需在面板上显式标注"插值"。
- 双游标时追加 `Δt`、每曲线 `Δ值`、`最小/最大`（可选）。

### 3.5 窗口 / 缩放 / 查询 的关系（关键设计点）

现在 `trendZoomOf` 是**纯显示**的缩放（存的是数据窗口的 0~1 百分比，`minSpan = 0.04`、`dataZoom.inside.minValueSpan = 3000ms`），数据只查一次。区间一长就会失真：24 小时 x 2000 点，放大到 1 分钟只剩约 1.4 个点，图上几乎是空的。

两种做法：

- **A（省事，不推荐）**：仍“一次查全区间 + 只做显示缩放”，点数不足时在图内提示“数据分辨率不足，请缩小时间范围或提高点数”。
- **B（推荐）**：把“当前窗口”提升为**查询参数**：滚轮 / 框选 / 滑块 / 平移结束后（防抖 250~400ms）按新窗口重新查询，窗口越小聚合窗越小，足够小则直接取原始点（`agg=none`）。工具栏的“跟随”开关决定窗口是否随时间前移。

B 需要数据层支持：窗口状态 `{from, to, agg, maxPoints}`、防抖 + 请求作废（已有 generation）、按 `(widgetId, window)` 缓存。**P1 就要定下来**，否则查询层会返工。

### 3.6 游标生命周期

- 游标绑定**绝对时间**：窗口滚动（跟随）时游标随时间轴左移，移出视口后面板显示“游标在视口外”，不清除；暂停 / 平移回视口即恢复。
- 拖拽游标只在指针距竖线 ±6px 内生效，其余位置拖拽仍是平移时间窗。
- 单击落游标 vs 拖拽平移：位移 < 3px 且 < 250ms 记为“点击”，否则记为“拖动”。

### 3.7 其它小交互（低成本，建议一起做）

- **双击曲线上的点 = 在该采样点落游标**（比单击更准，直接吸附真实点）。
- **游标时间可输入**：面板上的时间可点开编辑、直接输 `HH:mm:ss` 跳转。
- **复制读数**：面板一个按钮一键复制"时间 + 各曲线值"（便于粘到工单）。
- **缩放到游标两侧**：面板上的 ± 按钮（或 `[` / `]`）以游标为中心缩放 —— 排查报警时最常用。

## 4. 数据方案

### 4.1 后端：新增批量查询接口（旧接口保持不动）

```http
POST /api/tags/history/query
{
  "tagIds": ["demo.level", "demo.temp"],
  "start": "-1h",                       // 相对（-1h）或 RFC3339 绝对时间
  "stop":  null,                        // null/now() = 到现在
  "maxPoints": 1200,                    // 每曲线点数上限（10 ~ 5000）
  "agg": "auto"                         // auto | none | mean | max | min | last
}
```

```json
{
  "from": "2026-10-15T00:00:00Z",
  "to":   "2026-10-15T01:00:00Z",
  "series": [
    { "tagId": "demo.level", "unit": "%", "count": 1200, "downsampled": true,
      "points": [ { "time": "2026-10-15T00:00:01Z", "value": 42.6, "quality": "Good" } ] }
  ],
  "warning": null
}
```

错误语义沿用现有约定：`400 invalid_query`、`503 influx_unavailable`（body 仍为 `{ error, message? }`）。

实现要点：

- **一条 Flux 查多变量**：`filter(fn: (r) => r.tagId == "a" or r.tagId == "b") |> group(columns: ["tagId"])`，避免 N 次串行查询。
- **自动降采样**：`window = max(1s, ceil(span / maxPoints))`，用 `aggregateWindow(every: window, fn: agg, createEmpty: false)`；`agg = auto` 时数值用 `mean`、bool 用 `last`。响应里回传实际窗口，前端在标题上显示"按 30s 平均"。
- **不聚合时的取点顺序**：`sort(desc) |> limit(n) |> sort(asc)`，保证拿的是**最近** N 个点（修掉第 2.6 条的坑）。
- 上限保护：`tagIds ≤ 8`（与图元曲线上限一致）、`maxPoints ≤ 5000`。
- **只有数值字段能聚合**：`_field == "value"` 走 `aggregateWindow`；`_field == "value_str"`（字符串 / bool 文本）原样返回、不聚合，两类字段要分开处理。
- `aggregateWindow(..., createEmpty: false)`：空窗口不补点，图上留缺口（与实时趋势的质量断线语义一致）。
- **接口命名**：`POST /api/tags/history` **已被“写入历史样本”占用**。读接口建议 `GET /api/tags/history/batch?tagIds=a,b&start=&stop=&maxPoints=&agg=`（方便 curl 直接验证）；若坚持 POST，用 `/api/tags/history/query`，并明确“写入接口不动”。
- 旧接口 `GET /api/tags/{tagId}/history` 保留（老工程、单曲线路径还在用）。
- 复用 `InfluxHolder`，新增 `queryHistoryBatch(...)`；不改写入路径、不改 measurement/字段。

### 4.2 前端数据层（改造 `trendHistoryQuery.ts`）

- 查询粒度：由「每曲线一次」改为「每图元一次」：`requestTrendHistory(widgetId, tagIds, { from, to, maxPoints, agg })`。
- 缓存：`widgetId -> { range, maxPoints, agg, series: Map<tagId, {times, values, qualities}>, state, error }`。
- 自动刷新：仅在「跟随 = 开」且区间是相对时间时按间隔刷新（默认 10s，可配 0=关闭）；绝对区间不自动刷新。
- 状态机：`idle | loading | ready | empty | error`，暴露给图元与工具栏（错误区分 `influx_unavailable` 与其它）。
- 保留对外读取函数（`trendHistorySeries` / `trendHistoryTimes`）签名不变，避免动渲染层。
- 请求作废沿用 generation 机制；切换区间时旧响应必须丢弃。
- **历史末端接实时值**：窗口 `stop = now()` 时，把该变量的当前实时值作为最后一个点补上（每 1s 追加），否则曲线末端会比页面上的实时值"旧一点"；`stop` 是绝对时间时不补。
- **同时间戳去重**：同一变量同一时刻可能有两条（写值 + 质量变化各一条），按时间去重保留最后一条，并按时间升序排序后再画。
- **超时与取消**：`request()` 没有默认超时（只有 `healthCheck` 设了 2.5s）。批量查询要单独设 15~30s 超时 + `AbortController`，切窗口 / 离开页面时取消，避免慢查询堆积。

### 4.3 API 客户端

`apps/web/src/shared/api/client.ts` 增加 `apiQueryTagHistory({ tagIds, start, stop, maxPoints, agg })`，继续统一走 `request()`（带 token / 超时），不在组件里裸 fetch。

## 5. 渲染与实现要点

- **架构不变**：图表本体仍复用 `buildTrendChartOption`；未旋转、无业务的图元走**原生 ECharts 叠层**（`trendChartLive`），旋转或带事件的图元走**位图 + 手工转发**（`trendChartInteraction`）。
- **缩放**：`dataZoom` 由 `inside`-only 改为 `[inside, slider]`（`DataZoomSliderComponent` 已在 `trendChartLive` 注册，之前刻意去掉底部滑块，历史趋势需要它）；`toolbox.feature` 增加 `dataZoom`（框选）与 `restore`，保留 `saveAsImage`。
- **游标**：优先用 ECharts `graphic`（可拖动 + 自绘手柄）画竖线，读数面板用 HTML（与工具栏同一层，样式统一）；`markLine` 仅作退路（不能拖动）。
  - 吸附：对每条曲线的 `times` 二分查找最近点；面板标注"吸附点 HH:mm:ss"。
- **运行态状态**（游标位置、跟随开关、当前窗口）：放运行时内存（按 `widgetId`），**不写工程 JSON**，与 `trendZoomOf` 同一思路。
- **工具栏挂载**：新增 `components/runtime/TrendHistoryToolbar.vue`，按图元 `clientRect` 换算定位（复用 `historySearchClientRect` 的做法，新增 `trendToolbarClientRect`），在 `Canvas2DRuntime.vue` 与 `Canvas2DBoard.vue`（实时预览）各挂一处，与 `AlarmHistorySearchBar` 并列。
- **登录/权限**：工具栏按钮沿用图元 `visible` / 运行端交互开关判定；不可交互（设计端拖动状态）时 pointer-events 关闭。
- **实时趋势不受影响**：所有新增行为都挂在 `isHistory === true` 分支；实时趋势保持现在的默认外观与交互。
- **底部滑块只在原生路径启用**：`trendChartLayout` 现在明确不给滑块留高度（注释：绘图区高度全给曲线）。位图路径（旋转 / 带事件的图元）里滑块会“画出来但拖不动”，因此位图路径 **不画滑块**，只保留悬停读数 / 平移 / 游标；框选缩放同理仅原生路径提供。
- **导出 CSV**：加 UTF-8 BOM，否则 Excel 打开时间列 / 中文会乱码。
- **3D 面板**：`panelKonvaRuntime` 里的历史趋势也要挂同一套工具栏 / 游标；若 P1 先不做，就在文档里标注“面板内暂为只读”，避免现场以为是 bug。

## 7. 分阶段计划

### P1 时间与缩放（基础体验）· 约 1 天

- 后端批量查询接口 + `InfluxHolder.queryHistoryBatch`（含聚合与"取最近 N 点"修正）。
- 前端 `trendHistoryQuery` 改为按图元批量查询 + 状态机（loading/empty/error）。
- 工具栏：区间快捷 / 自定义区间 / ◀▶ 平移 / 跟随开关 / 刷新 / 导出图片。
- 图表：底部缩放滑块 + 框选缩放 + 双击还原。
- 加载中/无数据/历史库不可用 三种提示。
- **验收**：选 24 小时能出完整曲线（不再是只开头几分钟）；能缩放平移；停掉 Influx 有明确提示且页面不崩。

### P2 游标 · 约 1 天

- 单击落游标、拖动、←/→ 微调、Esc 清除。
- 读数面板（时间 + 各曲线值 + 质量色点 + 吸附标注）。
- 图例值改为"游标处（无游标时=最新历史点）的值"。
- **验收**：游标读数与悬停 tooltip 一致；时间精度到秒；吸附点标注清楚。

### P3 双游标与导出 · 约半天

- A/B 双游标、Δt 与各曲线 Δ值、可选最小/最大。
- 导出 CSV（当前窗口点表 / 游标读数表）、导出图片（已有）。

### P4 变量与打磨 · 约半天~1 天

- 设计端变量多选表格（搜索、批量添加、排序、线宽、图例名）。
- 运行端变量增删（若确认允许）。
- 快捷键提示、右键菜单、暗色主题细节、窄图元的自适应（工具栏按钮折叠为下拉）。

## 8. 风险与取舍

| 风险 | 处理 |
|------|------|
| 旧工程/旧接口兼容 | 只新增接口与可选字段；旧 `GET /history` 保留 |
| `limit` 只取最早 N 点（现存坑） | P1 必修，否则长区间"右边没数据" |
| 聚合掩盖毛刺 | 默认 auto，但界面必须显示"按 X 秒平均/最大"；可切 `none` 看原始点 |
| 点数与性能 | 8 曲线 × ≤2000 点；响应可能 1~3MB，必要时封顶 5000 并提示 |
| 时区 | 后端统一 RFC3339（UTC），前端按本地时区显示与选择；避免"差 8 小时" |
| 游标取值语义 | 默认吸附真实点并标注；插值必须显式标注，避免误读 |
| 旋转/带事件的图元走位图路径 | 高级交互（框选、双游标）仅原生路径提供；位图路径至少保证游标读数 |
| 坏质量点 | 与实时一致：Bad/Offline 断线（可选标红），并在读数面板显示质量 |
| 新依赖 | 不引入；全部用 ECharts + Element Plus 现有组件 |
| 批量查询可能较慢（Influx 扫全区间） | 客户端 15~30s 超时 + `AbortController` 取消；服务端同参数短时缓存；聚合窗口随跨度自动放大 |
| 历史完全依赖 Influx（未部署就没历史） | 保持"503 + 明确提示"；是否要 MySQL/文件兜底历史另议（见 §10.3 C7） |
| Influx 长期保留策略 | 部署建议：bucket 设保留期 + 按小时/天降采样任务；大数据量下趋势只查聚合结果 |

1. `pnpm typecheck` 通过（web + core）。

## 11. 需要确认的几件事

1. **运行端是否允许直接改变量**（加/删/换）？还是只在设计端配置、运行端只允许图例显隐？
2. **是否需要双游标（A/B 差值）**？现场排查常用，但 UI 会变复杂。
3. **Influx 现在是否已在跑**？P1 需要拿真实历史数据实测；否则只能靠空库/伪造数据验证。
4. **缩放 / 框选后是否按新窗口重新查询**（详见 §3.5，建议 B：按窗口重查）。这条决定数据层架构，建议先定。
5. **跟随开启时游标怎么处理**（详见 §3.6：建议绑绝对时间、移出视口保留）。
6. **3D 面板里的历史趋势是否同期上**（同样的工具栏 / 游标）？
7. **历史趋势末端要不要接实时值**（§4.2：建议接，让曲线末端与页面上的实时值对齐）？
8. **现场是否都装 Influx**？没装的话历史趋势就只能空着（是否要做兜底历史，见 §10.3 C7）。
