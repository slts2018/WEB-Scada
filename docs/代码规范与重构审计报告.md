## 关键结论

当前仓库是可用的 **Vue3 + Fastify pnpm monorepo 组态原型**，主链路（设计 → 动画/Tag → 发布 → Runtime 实时）已通。

最大缺口不是命名风格，而是：

1. **安全处于内网演示级**（全 API / WS 无鉴权）  
2. **工程化护栏缺失**（无 ESLint / Prettier / 测试 / CI）  
3. **若干 God 文件**（`project.ts`、`Canvas2DBoard.vue`、`app.ts`）阻碍后续治理  

重构应以 **冻结核心契约与 Designer/Runtime 语义** 为前提，先做护栏与拆分，禁止为规范强行换栈。

## 3. 项目架构（实际）

### 3.1 前端链路

```text
Views (Designer / Runtime)
  → Layouts / Components
  → Pinia Stores (project / tag / outputLog)
  → shared/api/client (fetch)
  → /api (Vite 代理)
  → Fastify
```

辅助层：`shared/konva`、`shared/three`、`shared/runtime`（绑定/动画执行）、`shared/storage`。

**特点**：几乎没有独立 composables / domain 层；业务大量落在 Store 与大型 SFC。

### 3.2 后端链路（非经典三层命名）

```text
app.ts（路由全集）
  → services/*（tagRuntime / resources）
  → store.ts（工程持久化门面）
  → db/mysql | db/tags | db/influx
     或 store.file（MySQL 不可用回退）
```

**特点**：路由直接调服务/DB；无独立 Controller/DTO/全局异常层；参数校验多为手写 `if`。

### 3.3 模块依赖

```text
@web-scada/core  ←  @web-scada/web
                 ←  @web-scada/server
```

未见包级循环依赖。`core` 作为契约层是正确方向，应继续守住。

## 4. 后端架构评价

| 观察 | 说明 |
|------|------|
| God Router | `apps/server/src/app.ts`（约 369 行）集中几乎全部 HTTP/WS |
| 持久化 | `store.ts` 门面 + MySQL / 文件双实现，职责清晰 |
| Tag 运行时 | `services/tagRuntime.ts`：内存 Map + 定时采样 + WS 广播 + 可选写 Influx |
| SQL | `mysql2` 参数化；未见字符串拼 SQL |
| 事务 | 以单语句为主，无显式事务边界 |
| 异常 | 路由内 `reply.code`；无统一业务异常/错误码枚举 |
| 日志 | Fastify logger；历史写入处存在空 `catch`（保实时、但可观测性弱） |

> Java/Spring 专节（Bean、@Transactional、MyBatis 等）**不适用**本仓库；等价关注点已映射到 Fastify/mysql2 上。

## 7. API 架构（摘录）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 健康与双库状态 |

## 8. 并发模型

- Tag 运行时：`setInterval` 采样 + 进程内 `Map` + WS 广播  
- 上传：单文件流式落盘  
- 无线程池 / 无分布式锁；单进程假设  
- 风险点：客户端暴增时广播放大；历史写失败被吞掉后无指标

- `app.ts` → `routes/projects|tags|settings|resources`

- `Canvas2DBoard` 交互抽 hooks / 命令对象

---

## 21. C 类：第一阶段禁止修改

- 工程 JSON / `PublishPackage` 契约与字段语义  
- `AnimationLink` / 属性绑定执行语义（Runtime 表现）  
- WebSocket Tag 报文协议（`tag.delta` 等）  
- Designer / Runtime 主交互闭环的行为变更  
- MySQL / Influx 写入语义与回退策略  
- 强制换栈：Spring Boot、Redis、MyBatis/JPA、换库  
- 未要求的 Flight `.hpg/.dhp` 二进制兼容  
- 为了“好看”改变运行逻辑或前后端数据格式  

---

## 22. 重构风险

1. 拆 Store / 画布易打断撤销栈与选中同步  
2. 动 `bindingEngine` 易造成 Runtime 与 Flight 操作习惯漂移  
3. 加鉴权若未兼容 Vite 代理，开发环境易全面 401  
4. 无测试时大改只能靠手工回归

## 附录 B：与「阿里 Java 手册」的适用关系
